# AI Agent 汇报页版式精简设计

## 目标

在保留集团工作汇报风格、真实界面证据和阶段性表述边界的前提下，降低 Multi-Agent 工作流的视觉复杂度，突出 Codex 与 Hermes 的核心职责，并显著放大右侧真实 APP 界面。

## 页面结构

- 左侧约 18%：压缩“已有基础、升级方向、建设目标”，每项只保留一句结论。
- 中部约 32%：使用简化的原生可编辑工作流，避免六个专业 Agent 横向铺开。
- 右侧约 46%：放大真实 APP 截图；截图下方仅保留“任务配置、协同工作流、多格式输出”三个短标签。
- 底部：保留阶段小结，压缩为一段结论式文字。

## 简化工作流

主流程采用四层结构：

1. 任务入口：需求、资料、模板。
2. Multi-Agent 编排中枢：任务理解、路由、状态管理。
3. 两类核心执行能力：
   - Hermes：数据收集、来源整理、资料归纳。
   - Codex：任务规划、结构设计、报告与 PPT 生成。
4. 审核与交付：来源核验、逻辑检查、多格式输出。

审核结果通过一条虚线反馈回路返回编排中枢，表达可迭代修正，而非一次性线性生成。

## 内容边界

- 当前界面和 MVP 流程作为已具备的开发基础。
- Multi-Agent 深度协同、审核闭环和知识沉淀继续使用“规划、拟升级、下一阶段”等措辞。
- 不增加未经确认的完成状态、效率数据、投资收益或部署结论。

## 视觉与验收

- 沿用新微 Logo 蓝、深蓝、蓝灰与浅灰配色。
- Logo 和界面截图保持原始比例，不修改截图业务内容。
- 架构节点、文字、连接线均为 PowerPoint 原生可编辑对象。
- 最终仍为严格 1 页、16:9；检查文字截断、元素重叠、页面溢出和箭头方向。
- 右侧界面在整页预览中应明显大于上一版本，并成为仅次于主标题的视觉重点。
